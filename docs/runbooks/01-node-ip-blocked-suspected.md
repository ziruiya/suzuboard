# 01 · 节点疑似被封（入口 IP 大陆不通）

## 症状
- 某条线路大陆客户端连不上/超时，但海外测速正常、机器本身活着、agent 在线。
- 历史定性（Issue #9，2026-11-19 结案）：大陆方向按 IP 的入境源过滤——SYN-ACK 在大陆侧被丢弃，ping.pe 大陆 13/13 探针失败、海外约 160 个全过，BGP 干净。被封 IP 不可逆，换端口、换 SNI 都救不回来（台湾机 2026-11-21 实证：8 个端口 SYN 全部被丢）。

## 适用契约
- 入口为公网 IP 直连的契约：A 组全部、B/C 组直连条目、VIP 临时直连条目（节点 26/46）。
- 经 VX 中转的条目先排除中转问题（手册 03）；IPv6-only 条目走手册 06。

## 只读诊断
1. 双视角探针：从上海机（大陆视角）与香港机（海外视角）分别用 sing-box 按契约参数实测 generate_204 ×2 + 出口 IP。大陆失败 + 海外成功 = 入口 IP 被封的特征签名。
2. ping.pe 对目标 IP 做全球 ping：大陆全红、海外全绿可佐证。
3. 查时间线：该 IP 上线时间、是否一上线就满负荷、来源商家（wap.ac 供应的机器占了历次坏 IP 的多数，666clouds 有 2 台；新 HK2 2026-11-19 上线、两天内被封，且首夜就有 11.8s 迟滞——IP 到手即脏）。
4. 排除伪装：机器 agent 在线、端口监听、证书有效、面板节点 enabled——这些都正常才谈「被封」。

## 修复动作
- 被封 IP 没有修复手段，只有替换：新机/新 IP 按手册 10 接入（先隔离观察 2–3 天再上生产），然后按契约类型切换：DNS 型走手册 02，VX 型走手册 03。
- 订阅侧零动作：域名、端口、协议参数全部不变，用户不更新订阅即可恢复——这是契约制度存在的意义。

## 发布前检查
- 新 IP 已通过手册 10 的隔离观察与预检（overall=passed，degraded 不算过）。
- 旧 IP 的处置已定：退机/取消请求走商家工单（措辞只写「TCP 回程丢包」，绝不提墙/GFW）。

## 用户侧验证
- 上海机 sing-box 按旧订阅参数实测 204 ×2、出口 IP = 新落地 IP。
- 巡检号订阅逐字节与切换前一致（本来就不该变）。

## 停手条件
- 双视角结论矛盾（大陆海外都失败）→ 不是被封，是机器/服务故障，转常规排障，别换 IP。
- 同一 /24 连续两台新机快速被封 → 停手上报，整段可能已被标记，换段/换商家再继续。

## 回滚与审计
- 切换类动作的回滚见手册 05。被封判定与处置过程记入事故记录（手册 11）：IP、上线时间、探针结果、商家与段信息，供后续采购避坑。
