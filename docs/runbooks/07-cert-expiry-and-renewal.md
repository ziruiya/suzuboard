# 07 · 证书到期与续期（Certificate Expiry）

## 症状
- B/C 组节点 TLS 握手失败、客户端报证书错误，或巡检发现某域名证书剩余天数告急。证书问题与被封的区别：海外视角也失败，且失败点在 TLS 层而不是 TCP 层。

## 适用契约
- 所有带 TLS 的契约：B 组（Trojan+gRPC）、C 组（VLESS+WS）、经 CF 的实验条目。A/VIP 的 Reality 不用证书，不在本手册。
- 现行事实：节点证书由落地机 agent 以 DNS-01（Cloudflare）向 Let's Encrypt 签发，90 天周期；台湾 IPv6 条目证书到期 2027-02-19；C 组经 Cloudflare 橙云的实验拓扑用的是 CF Origin CA 证书（另一套有效期口径，不要混）。

## 只读诊断
1. 在 VM/任意海外机用 openssl 读真实边缘证书（注意：VM 出口有 TLS 拦截代理，读边缘证书要走 `openssl s_client -proxy` 经出口代理，或直接在落地机本地查 cert 文件与 agent 日志）。
2. 核对证书域名覆盖契约 SNI、签发者、到期日；再核 agent 的续期日志有没有连续失败（DNS-01 失败多因 CF token 权限或域名已迁走）。

## 修复动作
- 续期失败：先修 DNS-01 的前提（域名仍在本方 CF 区、token 有该区 DNS 权限），再触发 agent 重新签发；签发成功后 toggle 节点（关闭→等待约 170s→开启，短 toggle 不生效）让新证书加载。
- 域名刚切换到新机时：DNS 未生效前不要 toggle 节点——agent 签不到证书会把节点拖死；顺序是 DNS 生效 → 证书签发成功 → 再启用节点。
- 证书域名与契约 SNI 不符：这是配置错误不是续期问题，按契约把节点 tls_settings.server_name 改回，或按漂移流程处理（手册 00/04）。

## 发布前检查
- 新证书链完整（fullchain）、域名覆盖、到期日 >30 天。
- 落地机本地用 openssl 直连 server_port 验证呈递的正是新证书（不要只看面板）。

## 用户侧验证
- 上海机 + 香港机各 sing-box 实测一次 204；客户端不再报 TLS 错误。

## 停手条件
- DNS-01 连续失败且原因不明：停手，不要反复重试把 LE 速率限制打满（同名证书有周配额），先查 token 与域名归属。
- 证书是 CF Origin CA 而入口已切到非 CF 路径：停手，这种证书公网不可信，必须换 LE 后再切。

## 回滚与审计
- agent 一般保留上一张证书文件；新证书异常时指回旧文件并 toggle 节点。每次续期/换证在当班记录留：域名、旧到期、新到期、签发方式。
