# 06 · IPv6-only 节点（IPv6-Only Nodes）

## 症状
- 某机 IPv4 被封但机器自带 IPv6 段可用（台湾机模式：IPv4 85.237.207.145 全端口 SYN 被丢，但其 /64 IPv6 大陆可达），需要靠 AAAA-only 域名续命；或现行 IPv6 条目（节点 56/57）出问题。

## 适用契约
- 节点 56「B组台湾①·IPv6」（tw6.suzu.club:8446，Trojan+gRPC）、节点 57「C组台湾①·IPv6」（twc6.suzu.club:8448，VLESS+WS）。
- 结构要点：AAAA-only 独立域名（**绝不**在被封的 A 记录旁并排加 AAAA——客户端可能先撞 v4，Shadowrocket 的 v6 偏好不可靠）；端口用 8446/8448 而不是沿用 8443/8444（xboard-node 一机一监听，同机同端口冲突会打死原节点 22/34）。

## 只读诊断
1. 确认 AAAA 记录存在且只有 AAAA、无 A 记录（CF API 读回）。
2. 从大陆视角（上海机需有 IPv6 出口时）或支持 v6 的探针实测：sing-box 走 v6 条目 204 ×2、出口为该机 IPv4（服务端双栈，出口仍是 v4 属正常）。
3. 证书：agent 以 DNS-01 签发，现行证书到期 2027-02-19；临近到期先查 agent 续期日志。

## 修复动作
- AAAA 被误删/误改：按备份（swap-backup 内的 cf-suzuclub-tw-records 快照）恢复 AAAA 值。
- 机器换 IPv6 段：更新 AAAA 到新段地址，契约的 legacy_hostname 不变、订阅零改动；若同时换了端口则属于契约漂移，必须走新契约版本流程并评估旧订阅失效面——能不换端口就不换。
- 新增同类条目：照 56/57 的模板复制（同机、独立 AAAA-only 域名、错开端口、同 profile），上线前双视角验证。

## 发布前检查
- 域名 A 记录为空、AAAA 正确——这是本手册最容易犯的错（顺手补 A 记录等于把用户送回被封的 v4）。
- 新条目 show 与 rollout_stage 双闸：`show=1` 且 profile rollout_stage='production' 才进订阅。

## 用户侧验证
- 仅 v6 可用网络下的客户端能连；明确告知：v4-only 网络的用户用不了这两条，它们是补充线路，不是全量替代。
- 覆盖率门槛：全量推广前需 ≥100 活跃用户、7 天可达率 ≥90%（GPT 收敛口径），未达标前只作附加条目。

## 停手条件
- 目标机器没有可路由的公网 IPv6（只有链路本地地址）：停手，此路不通，回手册 01 的换机路径。
- AAAA 指向的 v6 地址在大陆也开始丢包：停手记录，说明过滤已扩到 v6，按换机处理。

## 回滚与审计
- 回滚 = 删除/恢复 AAAA 到备份值；原 v4 条目（22/34）自始至终不动，不存在连带回滚。变更记入当班记录与事故档案（手册 11）。
