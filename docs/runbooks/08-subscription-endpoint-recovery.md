# 08 · 订阅端点故障（Subscription Endpoint Recovery）

## 症状
- 用户连订阅都拉不到（订阅域名被封/解析异常/面板故障），或拉到的订阅是空的/旧的。线路本身好坏另说——订阅通道死了，用户连「自救」都做不到，这是设计上要根除的单点：老用户靠已缓存订阅+契约不变继续用，新用户与换设备用户靠本手册恢复订阅通道。

## 适用契约
- 订阅入口 www.suzu.life（面板本体，走 Cloudflare proxied A 记录）与订阅路径 `/s/{token}`。
- 关联资产：面板容器 wwwsuzulife-xboard-1、工单桥 ticket-bridge.service、巡检号 429 的订阅（日常基线哈希就存它）。

## 只读诊断
1. 分层：DNS 解析（公共 DoH 查 www.suzu.life）→ CF 边缘（curl -I 看是否 CF 应答）→ 源站（面板机本地 curl 127.0.0.1 对应端口）→ 应用（容器状态、日志）。
2. 拉巡检号订阅，与基线逐字节比对：内容变了先查是谁改了节点/模板，不要先怀疑用户。
3. 若只是大陆拉不到、海外正常：订阅域名/IP 被针对，按修复动作走备用域名路径。

## 修复动作
- 面板故障：按面板发布/回滚流程处理（手册 05 的面板回滚），恢复后先验巡检号订阅字节与事发前一致。
- 订阅域名大陆不可达：启用备用订阅域名（同面板、不同域名解析），在客户端下载页与公告中同步新地址；老域名不删，恢复后仍是主入口。注意新域名若走 CF，Turnstile 放行名单要同步加上新域名（2026-11-13 POCO 事故：故障转移域名没进 widget 名单，注册/找回的人机验证直接不出题）。
- 订阅内容异常（节点缺失/参数变样）：这是契约漂移问题，回手册 00/04，不要在订阅模板上打补丁掩盖。

## 发布前检查
- 备用域名证书有效、解析已生效、订阅路径可达且返回内容与主域名逐字节一致。
- 任何新故障转移域名同步进 Turnstile widget 放行名单与客户端远程域名清单（domains.txt 口径）。

## 用户侧验证
- 大陆网络下真实客户端（Clash Verge / Shadowrocket）拉订阅成功并能连任一线路。
- 老用户旧订阅不刷新也能继续用（契约不变原则的日常验证）。

## 停手条件
- 面板数据库异常（订阅内容大面积变化且无人操作）：停手，先备份数据库再查，不要重启容器碰运气——重启前按生产规矩备份（MySQL 在宿主机，先 mysqldump）。
- 主、备订阅域名同时不可达：停手升级用户，这已不是单点故障。

## 回滚与审计
- 订阅通道的变更（新域名启用、模板调整）都要在当班记录留痕；面板侧回滚见手册 05。事后按手册 11 补事故记录：影响面是「拉不到订阅」还是「内容错误」，两者严重度完全不同。
