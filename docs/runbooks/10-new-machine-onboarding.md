# 10 · 新机接入（New Machine Onboarding）

## 症状
- 买了新 VPS 准备接替被封/退役的落地机。历史教训：新 IP 一上线就满负荷是 Issue #9 的促成因素之一；新 HK2 到手即脏、上线两天被封。接入纪律的目标是：坏 IP 在隔离期就暴露，不带病上生产。

## 适用契约
- 目标是成为某份或某几份契约的新 origin（binding 的 origin_id / standby_origin_id）。
- 采购前置：避开已知脏段与 wap.ac 的问题批次（历次坏 IP 多数来自它）；同 /24 刚烧掉一台时不要在同段补货（新 US1 与被封的旧 US1 同 /24 是已知风险项，靠观察期兜底）。

## 只读诊断（隔离观察期，2–3 天）
1. 到手当天：ping.pe 全球测 IP——大陆探针若已大面积失败，这台到手即脏，直接换货/退款，不要观察。
2. 观察期每天：上海机 + 香港机双视角 sing-box 冒烟（临时配置，不进面板），记录延迟与丢包；首夜迟滞异常（如 HK2 的 11.8s）视为黄牌，两次黄牌退货。
3. 查 IP 历史声誉只能作参考，最终以双视角实测为准。

## 修复动作（接入流程）
1. 装 Tailscale（tag:infra）+ xboard-node agent（用自家仓库 ziruiya/xboard-node 的 install.sh），机器在面板建档或复用被替换机的 machine 记录（按当班口径，换机桥接期复用旧 machine id 的做法已有先例，须留记录）。
2. 在新机按契约把服务配齐：同 server_port、同协议与 transport、同 SNI 证书（DNS-01 先行）、Reality 密钥对与原机一致（密钥对是契约的一部分，换机不换钥）、gRPC 服务名/WS 路径逐字一致。
3. 跑预检（手册 04）：overall=passed 才进入切换。
4. 切换：DNS 型走手册 02，VX 型走手册 03；切换后新机先单线灰度（一个节点），稳 24h 再迁同机其余节点。

## 发布前检查
- 观察期记录完整（≥2 天、双视角、无黄牌未解释）。
- 预检 passed；新机证书、监听、agent 心跳全正常；旧机保持可回滚状态至少 48h（不要切换完立刻退旧机）。

## 用户侧验证
- 切换后按手册 02 的用户侧验证执行；另在晚高峰（21:00–23:00 大陆时段）复测一次延迟，隔离期测不出晚高峰拥塞。

## 停手条件
- 观察期任一大面积大陆不可达：停手，换货，不要「先上生产看看」。
- 新机与契约对不齐且原因不明（密钥对不上、服务名不一致）：停手对账，不要改契约迁就新机——契约服从订阅，不是反过来。

## 回滚与审计
- 灰度期回滚 = 切回旧机（手册 05），新机继续观察或退货。接入全程在当班记录留：商家、IP、段、观察数据、预检结果、切换时间。
