# 09 · 旧机桥到期硬截止（Bridge Expiry Deadlines）

## 症状
- 四条 VX 规则仍借道旧机做桥，旧机到期日就是桥的死亡时间。不是「可能出问题」，是到期必断：
  - 节点 53（browser-us）← 旧 US1（81.31.232.170），到期 **2026-12-02**
  - 节点 50（V-HK2）← 旧 HK-B（45.149.92.153），到期 **2026-12-04**
  - 节点 49（V-HK1）← 旧 HK-A（154.36.148.215），到期 **2026-12-13**（取消工单已提交、到期取消，供应商待确认）
  - 节点 6（R-SGA）← 旧 SG（185.151.146.61），到期 **2026-12-15**
- 另注意：VX 流量包本身 2026-12-05 到期；旧 UK 机（86.53.185.217）2026-12-03 到期（健康 IP，值得续费，与桥无关但同窗口）。

## 适用契约
- 上述 4 个节点的契约（entry_mode='vx'，目标仍指向旧机）。
- 前置事实：这些旧 IP 多数已被封或退役中，桥的价值只在 VX 入口区是好区；规则改指新机必须等好区窗口（手册 03）。

## 只读诊断
1. 每周（截止前两周起每 48 小时）核对：规则现行目标、四台旧机的供应商后台到期日与状态（666clouds / wap.ac 口径不同：666 看实例到期，wap.ac 无自动续费、欠费即停）。
2. 核对取消工单状态：旧 HK-A 的到期取消工单（#338073）若被供应商提前执行，桥会提前死——状态变「已确认/已执行」立即按断桥处理。

## 修复动作（按优先级）
1. 好区窗口出现：按手册 03 把规则逐条改指新机（顺序按截止先后：53 → 50 → 49 → 6），改完一条验一条。
2. 窗口不来、截止逼近（<72h）：向用户提交裁决：a) 临时直连（节点 host/port 直指新机，牺牲中转隐蔽性，参照 26/46 现状）；b) 给旧机短期续费续命（被封 IP 续费只为保桥的 VX 目标可达性——注意桥目标机本身要在海外视角可达，被封不影响 VX 从海外连它）；c) 接受该线路到期断线并提前公告。
3. 桥断之后才发现的：按 b/a 顺序补救，并按手册 11 记事故——这是调度失误不是技术故障。

## 发布前检查
- 任一改指/直连动作前，该节点契约与现行规则定义已备份。
- 续费类动作必须经用户点头（花钱事项），不许自作主张续。

## 用户侧验证
- 每条处理完：上海机 sing-box 204 ×2、出口 IP 正确；订阅逐字节不变（临时直连会改节点 host/port 的除外——那种情况订阅内容会变，必须单独向用户说明影响面）。

## 停手条件
- 距截止 <24h 且无窗口、无裁决：停手并立即升级用户（最高优先级），不要赌供应商宽限期。
- 供应商后台显示旧机已终止：桥已死，停手走补救路径，不要再对规则做无意义删建。

## 回滚与审计
- 本手册的动作回滚见手册 03/05。每台旧机的最终处置（改指完成/续费/任其到期）在当班记录逐台销账，截止日过后复查四条线路状态并关账。
